# دليل نشر موقع «جمعية حاضنة الجمعيات»

استضافة احترافية على **Cloudflare Pages** للموقع، و**R2** لملفات الـPDF، مع مسار واضح لتحويل لوحة التحكّم إلى نظام فعلي عبر **Workers + D1** لاحقًا — دون هجرة مؤلمة.

> الأرقام والحدود في هذا الدليل محدّثة حتى يوليو 2026؛ راجع صفحات Cloudflare الرسمية قبل أي شراء، فقد تتغيّر.

---

## 1) المكدّس الموصى به ولماذا

| الطبقة | الأداة | الدور |
|---|---|---|
| الاستضافة | Cloudflare Pages | تقديم صفحات الموقع الثابتة عالميًا بسرعة وحماية |
| تخزين الملفات | Cloudflare R2 | استيعاب عشرات/مئات ملفات PDF بتكلفة زهيدة وبلا رسوم نقل |
| الخلفية (لاحقًا) | Workers + D1/KV | استقبال النماذج، تسجيل دخول حقيقي للوحة، حفظ الإعدادات ونشرها للجميع |

**لماذا هذا الاختيار:** يبدأ مجانيًا، سريع عالميًا، يفصل الملفات الثقيلة عن الكود، ويسمح بإضافة الوظائف الديناميكية لاحقًا على المنصّة نفسها — وهو ما يناسب فريقًا تقنيًا بسيطًا.

**ملاحظة 2026:** تعمل Cloudflare على دمج Pages ضمن Workers. الدليل يستخدم Pages (الأبسط الآن)، والمسار متوافق مع الانتقال إلى Workers لاحقًا عند الحاجة.

---

## 2) بنية ملفات المشروع

المجلد الذي سترفعه يحتوي على:

```
/ (جذر الموقع)
├── index.html                ← الرئيسية
├── about.html, programs.html, news.html, governance.html, contact.html
├── board.html, committees.html, team.html, assembly.html, endowments.html, licenses.html
├── volunteer.html, membership.html, jobs.html, satisfaction.html
├── 404.html                  ← صفحة الخطأ
├── admin.html, admin-login.html   ← لوحة التحكّم (نموذج أولي)
├── favicon.png, og-image.png
├── robots.txt, sitemap.xml
└── files/ (اختياري مؤقتًا)   ← ملفات PDF إن لم تستخدم R2 بعد
```

> **مهم:** لا ترفع ملفات الكود المصدرية (`site.py`, `build.py`, …) إلى الاستضافة — فقط المخرجات أعلاه.

---

## 3) قبل النشر: ضبط عنوان الموقع (SITE_URL)

الوسوم (canonical / Open Graph) وملفَّا `sitemap.xml` و`robots.txt` تحتوي حاليًا على العنوان المبدئي:

```
https://www.iaq.org.sa
```

- **للتشغيل التجريبي على نطاق فرعي مجاني:** يمكن تركه كما هو مؤقتًا (لا يؤثّر على العمل).
- **قبل الإطلاق الرسمي:** استبدله بنطاقك الحقيقي بإحدى طريقتين:
  1. **إن كان لديك مُشغّل الكود (Python):** غيّر قيمة `SITE_URL` في أعلى ملف البناء ثم أعِد التوليد.
  2. **بدون تشغيل الكود:** استخدم «بحث واستبدال» في محرّر نصوص عبر جميع ملفات `.html` و`sitemap.xml` و`robots.txt`، واستبدل النص المبدئي بنطاقك.

## 4) النشر على Cloudflare Pages

أنشئ حسابًا مجانيًا على Cloudflare. أمامك طريقتان:

### الطريقة (أ) — رفع مباشر (الأسرع للتجربة)
1. من لوحة Cloudflare: **Workers & Pages → Create → Pages → Upload assets**.
2. أعطِ المشروع اسمًا (مثل `association-incubator`).
3. اسحب مجلد الموقع كاملًا (كل ملفات الخطوة 2)، ثم **Deploy**.
4. خلال ثوانٍ يصبح الموقع متاحًا على رابط مثل: `association-incubator.pages.dev`.

مناسبة للانطلاق السريع؛ كل تحديث تعيد فيه رفع المجلد.

### الطريقة (ب) — ربط مستودع Git (احترافية وموصى بها)
1. ارفع ملفات الموقع إلى مستودع على GitHub.
2. في Cloudflare: **Create → Pages → Connect to Git** واختر المستودع.
3. الإعدادات:
   - **Build command:** اتركه فارغًا (الموقع جاهز، بلا بناء).
   - **Build output directory:** `/` (أو المجلد الذي يحوي `index.html`).
4. **Save and Deploy**.

الميزة: كل `git push` ينشر الموقع تلقائيًا، مع نسخة معاينة لكل تعديل، وسجل إصدارات للرجوع.

> الخطة المجانية تكفي تمامًا: نطاق تمرير غير محدود، و500 عملية بناء شهريًا، و5 نطاقات مخصّصة لكل مشروع، وحتى 20,000 ملف لكل موقع (الملفات الأكبر من 25 ميغابايت تُرفع إلى R2 — انظر القسم 6).

## 5) النطاقات: التجربة الآن ثم الإطلاق دون كسر الموقع القديم

موقعك القديم على النطاق الرئيسي — لن نلمسه حتى تجهز.

### المرحلة التجريبية (بلا مخاطرة)
- استخدم رابط `‎*.pages.dev` المجاني مباشرة، أو
- أنشئ **نطاقًا فرعيًا** للتجربة مثل `beta.اسم-الجمعية.org.sa`:
  - في إعدادات DNS لنطاقك، أضِف سجل **CNAME** باسم `beta` يشير إلى رابط مشروع Pages.
  - الموقع القديم على الجذر (`@` و`www`) يبقى كما هو دون أي تغيير.

### الإطلاق الرسمي (عند الجاهزية)
1. في مشروع Pages: **Custom domains → Set up a domain** وأضف `اسم-الجمعية.org.sa` و`www`.
2. حدّث سجلّي DNS للجذر و`www` ليشيرا إلى Pages (تُرشدك Cloudflare للقيم؛ وإن نقلت إدارة DNS إلى Cloudflare تتم تلقائيًا مع شهادة SSL).
3. تأكّد أن `SITE_URL` صار نطاقك الحقيقي (القسم 3)، وأعِد النشر.

> نقل الـDNS لإدارة Cloudflare يمنحك SSL تلقائيًا وحماية وأداءً أفضل، لكنه اختياري.

## 6) إدارة عشرات ملفات الـPDF عبر R2 (المحور المهم)

لا تضع مئات ملفات الـPDF داخل مستودع الموقع (يثقله ويبطئ النشر). ضعها في **R2** وأشِر إليها بروابط.

### الإعداد
1. من Cloudflare: **R2 → Create bucket** (مثل `ai-files`).
2. فعّل الوصول العام: **Settings → Public access** (رابط `r2.dev`)، أو اربطه بنطاق فرعي احترافي مثل `files.اسم-الجمعية.org.sa` عبر **Custom Domain** داخل R2.
3. ارفع ملفات الـPDF (سحب وإفلات من لوحة R2، أو أدوات متوافقة مع S3 مثل `rclone` للرفع بالجملة).

### الربط في الموقع
- في صفحات المكتبات (الحوكمة، التراخيص) استبدل روابط التحميل `#` برابط الملف على R2، مثل:
  `https://files.اسم-الجمعية.org.sa/policies/bylaws-2026.pdf`
- لاحقًا، عند تفعيل لوحة فعلية، تُدير الملفات من اللوحة مباشرة (رفع/حذف) عبر Workers + R2.

### الحدود والتكلفة (محدّثة يوليو 2026)
- **مجانًا شهريًا:** 10 غيغابايت تخزين، ومليون عملية كتابة، و10 ملايين عملية قراءة، و**نقل بيانات مجاني دائمًا**.
- **بعد التجاوز:** التخزين ‎$0.015 لكل غيغابايت شهريًا، مع بقاء النقل مجانيًا. مثال: 15 غيغابايت (≈ آلاف ملفات PDF) ≈ **‎$0.075 شهريًا** فقط.
- نصيحة أداء: اضبط ترويسة تخزين مؤقت طويلة على الملفات (`Cache-Control: public, max-age=31536000, immutable`) لتقليل عمليات القراءة.

## 7) لاحقًا: تحويل لوحة التحكّم إلى نظام فعلي

اللوحة الحالية نموذج أولي يعمل في المتصفح (localStorage + تصدير/استيراد JSON). لجعلها فعلية لكل الزوّار، أضِف طبقة خلفية على المنصّة نفسها:

| الوظيفة | الحل على Cloudflare |
|---|---|
| استقبال النماذج (تطوّع/عضوية/توظيف/تواصل) وحفظها | Workers + D1 (قاعدة SQL) |
| إعدادات الموقع (ثيم/نصوص/قوائم/أقسام) محفوظة ومنشورة للجميع | Workers + KV أو D1 |
| رفع/حذف ملفات PDF من اللوحة | Workers + R2 |
| تسجيل دخول حقيقي وصلاحيات | Workers + KV/D1 (جلسات) + تجزئة كلمات المرور |
| تحليلات زيارات حقيقية | Cloudflare Web Analytics (مجاني)، أو Plausible/Matomo |

خارطة طريق مختصرة:
1. فعّل **Cloudflare Web Analytics** فورًا (سطر سكربت واحد) لتحصل على زيارات حقيقية بدل الأرقام التجريبية.
2. أنشئ **Worker** لاستقبال النماذج وكتابتها في **D1**، واعرضها في صندوق الطلبات.
3. انقل حفظ إعدادات اللوحة من localStorage إلى **KV/D1** ليصبح النشر عامًّا.
4. أضِف **مصادقة** حقيقية لصفحة الدخول.

> حدود مجانية مريحة للبداية: D1 حتى 5 ملايين قراءة و100 ألف كتابة يوميًا و5 غيغابايت، وWorkers حتى 100,000 طلب يوميًا. الترقية المدفوعة بنحو ‎$5 شهريًا عند التوسّع.

## 8) ملخّص الحدود والتكاليف (يوليو 2026)

| البند | المجاني | المدفوع |
|---|---|---|
| Cloudflare Pages — نطاق التمرير | غير محدود | — |
| Pages — عمليات البناء | 500/شهر | من ‎$5/شهر (5,000) |
| Pages — الملفات لكل موقع | 20,000 (حد الملف 25MB) | حتى 100,000 |
| Pages — نطاقات مخصّصة | 5/مشروع | أكثر |
| R2 — التخزين | 10GB | ‎$0.015/GB/شهر |
| R2 — النقل (egress) | مجاني | مجاني |
| D1 — يوميًا | 5M قراءة / 100K كتابة / 5GB | ضمن Workers Paid |
| Workers — الطلبات | 100,000/يوم | 10M/شهر ضمن ‎$5 |

**البدائل باختصار:** Netlify (نماذج جاهزة لكن نطاق تمرير محدود مجانًا)؛ GitHub Pages (ثابت فقط، لا يناسب أهدافك المستقبلية)؛ استضافة cPanel أو VPS (تحكّم أكبر لكن إدارة تقنية أثقل).

## 9) قائمة تحقّق سريعة

- [ ] تجهيز مجلد المخرجات (القسم 2) بدون ملفات الكود المصدرية.
- [ ] إنشاء حساب Cloudflare.
- [ ] نشر الموقع على Pages (رفع مباشر أو ربط Git).
- [ ] التحقّق من الرابط `‎*.pages.dev` (تشغيل تجريبي).
- [ ] (اختياري) نطاق فرعي `beta.` عبر CNAME دون لمس الموقع القديم.
- [ ] إنشاء bucket في R2 ورفع ملفات PDF وربطها في صفحات المكتبات.
- [ ] قبل الإطلاق: ضبط `SITE_URL` بالنطاق الحقيقي وإعادة النشر.
- [ ] تفعيل Cloudflare Web Analytics.
- [ ] عند الجاهزية: تحويل الجذر و`www` للموقع الجديد.
- [ ] لاحقًا: طبقة Workers + D1 لتفعيل النماذج واللوحة فعليًا.
